The *Spring Boot starter* for https://github.com/alexmond/notify4j[notify4j], the embeddable
multi-channel notification library for the JVM. It binds the `notify4j.*` properties and
auto-configures the `Notifications` facade.

The Spring-free engine (`notify4j-core`) lives in the https://github.com/alexmond/notify4j[notify4j]
repo and keeps its own version. This repo is released *per Spring Boot line*.

📖 *Documentation:* https://www.alexmond.org/notify4j/current/

== Spring Boot compatibility

The starter version tracks the Spring Boot version it is built against:
`<boot-version>.<revision>`. Pick the line that matches your application.

[cols="1,1,1,1",options="header"]
|===
| Starter | Spring Boot | notify4j-core | Branch

| 4.1.1.x | 4.1.x | 1.1.1 | `main`
| 4.0.8.x | 4.0.x | 1.1.1 | `4.0`
|===

Starter versions up to `1.1.1` were released from the notify4j repo, on Spring Boot 4.0.

== Get started

[source,xml]
----
<dependency>
    <groupId>org.alexmond</groupId>
    <artifactId>notify4j-spring-boot-starter</artifactId>
    <version>4.0.8.1</version>
</dependency>
----

The starter pulls in `notify4j-core`. Declare a `NotificationAdapter` bean (it teaches notify4j
how to read your event type) and list channels under `notify4j.urls`:

[source,yaml]
----
notify4j:
  urls:
    - slack://hooks.slack.com/services/T000/B000/XXXX
    - pagerduty://<routing-key>?tags=failed
----

Then inject `Notifications` and call `notifications.send(event)`. The
link:notify4j-sample[`notify4j-sample`] module is a runnable example, and the
https://www.alexmond.org/notify4j/current/[notify4j reference docs] cover every property and
channel URL.

== Modules

[cols="1,3"]
|===
| `notify4j-spring-boot-starter` | Auto-configuration: binds `notify4j.*`; email and Micrometer metrics are optional.
| `notify4j-sample` | Runnable example app. Built under the `default` profile only; never published.
|===

== Build

[source,shell]
----
./mvnw verify -Pdefault    # build + test + quality gates, including the sample
----
